## 1. 逐项改动

### P-01 · 人工 CSV 能伪造官方价

**改法**：加两张名单。

```python
OFFICIAL_CHANNELS = {"cn_official","cn_trade","gw_uk","gw_us","gw_official"}  # 只允许系统写
MANUAL_CHANNELS   = {"manual","taobao","xianyu","cn_retail"}                  # 人工只能写这些
RESERVED_PLATFORMS = {"gw china rrp","gw china trade","element games"}
```

- channel 不在人工名单 → 拒绝并计数 `rejected_channel`；
- vendor 占用系统平台名 → 拒绝（唯一键含 platform，否则会覆盖官方当天的观测）；
- sku_id 命中但 sku_name 相似度 < 0.34 → 拒绝（防止名称与货号错位把价格挂错商品）。

**实测**：`channel=cn_official, price=1.5` 现在 `saved=0, rejected_channel=1`，库里的官店价不受影响。

### P-02 · `confidence=low` 只挡了"最佳价"

**改法**：把 low 贯穿到所有对外数字。

| 位置 | 改法 |
|---|---|
| 最低价 `lowest` | 参与候选前先过 `_usable()`——一条 ¥50 的错配闲鱼帖不能再盖过 ¥370 的官店价 |
| 涨跌 `price_movements` | SQL 加 `COALESCE(confidence,'medium') <> 'low'`，不再凭空造出 -50% |
| 行置信度 | 新增 `_weakest()`：取展示值里**最弱**的一个，不能拿官店价的 high 给闲鱼价背书 |

**真实数据验证**：`01-10 TRAJANN VALORIS` 原本显示"国内官店 ¥370 · 最低 ¥50 闲鱼"，
现在只显示"国内官店 ¥370"——那条 ¥50 的 low 观测不再出现在推送、报告和 `price` 命令里
（数据仍保留在库中，只是不参与展示）。

### P-03 · 海外匹配守卫可绕过

三道口子全堵上：

1. **没有匹配名直接拒绝**：拿不到 `matched` 就无法校验版本与品类，不能再"放行"；
2. **补齐版本标记**：`EDITION_TOKENS` 增加 `jp / jpn / japanese / deluxe / anniversary / collectors` 等；
3. **品类族细分**：`_category_family` 从 `mini/paint/terrain` 三档扩成
   `mini / paint / terrain / book / codex / boxed / accessory`——规则书不会再匹配到单个模型上。

**实测**：`Custodian Guard (Japanese)` → 拒；`Codex: Adeptus Custodes` 对模型商品 → 拒；
不传 `matched` → 拒。

### P-04 · 匹配阈值太松 + 提前 break

- CLI `--min-score` 默认 **0.55 → 0.7**（0.60 的兄弟商品 `CUSTODIAN GUARD` vs `CUSTODIAN WARDENS` 会被挡住）；
- 查询变体不再"一达标就 break"，只有匹配度 ≥ **0.85** 才提前收工，否则继续试更精确的尾部查询。

### P-05 · `observed_at` 是自由字符串

- 新增 `normalize_observed_at()`：`2026-11-17T09:00:00+08:00`、`2026/11/17` 一律归一成 `2026-11-17`，
  解析不了返回空串由调用方拒绝；
- 三个入口（Excel / 手工 CSV / 海外价）全部走它；
- 唯一键 `(product, channel, platform, observed_at)` 因此不会再被格式差异绕过。

**实测**：同一天用两种格式各导一次，库里只有 1 行（修复前是 2 行 + 20% 假涨跌）。

### P-06 · Excel 导入静默丢价

| 情况 | 以前 | 现在 |
|---|---|---|
| 表里没有 New 列（8 列） | 0 个价格点，退出码 0 | 用 Current 记录，note 标注"表内无新价" |
| New 列存在但该行空 | 该商品无价格点 | 回退 Current |
| 合并单元格导致续行货号为空 | 整行丢弃 | 继承上一行货号 |
| 数字格式货号 `9901` | 整行跳过 | 接受（`\d{4,}`） |
| 负价 / 零价 | 入库并可能成为最低价 | 拒绝并计数 `invalid_prices` |
| 一个价格点都没写入 | 报成功 | `error` + CLI 退出码 3 |

表头也改成**按列名识别**（找含 `CNR/CNB/New` 的列），认不出才退回固定 5/6/7/8。

### P-07 · 涨跌把不同卖家当时间序列

`price_movements` 改为按 `(product, channel, platform)` 取序列；同一渠道下若出现多个平台
（淘宝/闲鱼多家卖家），**整条渠道跳过**——不同卖家的报价不是时间序列。
官店/海外零售这类单一平台渠道照常计算。

**实测**：同一天 `卖家甲 ¥300 / 卖家乙 ¥100` → 不再产出 -66.7%。

### P-09 · 预期价写死 GBP

`expected_price(amount, currency, cfg)`：币种跟着价格走。
`gw_us` 的美元价不会再被当成英镑乘 9.2；没有对应汇率时返回 None（宁可不给）。

**实测**：同样的 100 单位，USD 的预期价低于 GBP（7.2 < 9.2 汇率），未知币种（JPY）返回 None。

### P-13 · 清理命令误删正确价格

`note` 里改存**完整匹配名**（原来截断到 40 字），`purge_mismatched_overseas` 反查时不会再
"因为语言标记落在第 40 字之后"而把正确价格判成版本不一致。

**实测**：一个 76 字、带 `Limited Edition Chinese` 的正确匹配，purge 后 `removed=0`。

### P-14 · 负价

`_valid_price()`：必须是正的有限数（`NaN` 也不等于自己）。
Excel / 手工 CSV / 海外价三条路径都过这一关。

### P-15 · 槽 5 链接可写入 `javascript:`

新增 `_safe_url()`，只放行 `http://` / `https://`。槽 5 的 `url` 在 `build_slot5_rows`
就清洗掉，模板拿到的永远是安全值（推送侧本来就有过滤，现在两边一致）。

### A-08 · 自动导入的 mtime 基准会被冲掉

`auto_refresh` 原来取"最后一条 price_runs"，只要中间跑过一次 Excel 导入（那条没有 `csv_mtime`），
基准就归零，CSV 没变也会重导。改为只查**带 `csv_mtime` 的最近一条**。

### 附带：国内价的置信度不再一律 high

`--fetch-cn` 以前"样本 ≥3 条就标 high"。3 条闲鱼挂牌不等于已核实，改为：

```
样本 ≥8 → high    样本 3–7 → medium    样本 <3 → low
```

## 3. 仍然存在的限制（如实记录）

1. **`expected_price` 在真实数据上依然不可达**：线上 1745/1745 个商品都有 `cn_official`，
   而模型只在"有海外价且无官店价"时才启用。这不是 bug，是数据现状；
   要么补没有官店价的商品数据，要么删掉这一列。**建议保留**——它现在至少是正确的（币种不再写死）。
2. **Excel 导入没有真实调价表可验**：仓库里没有 GW 官方 xlsx，六个用例都是合成表。
   真表到手后要再跑一次确认表头能被 `_excel_layout` 认出来（识别失败会退回固定列位）。
3. **Element Games 的 DOM 没联网验证**：rrp/sale 的取值顺序仍是原假设，这轮没动抓取脚本。
4. **涨跌只覆盖单一平台渠道**：多卖家渠道直接跳过，所以"闲鱼降价"这类事件不会出现在槽 5——
   这是有意的取舍，但意味着槽 5 的"涨跌"列实际只会由官店/海外价触发。
