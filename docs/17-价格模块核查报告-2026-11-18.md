## 2. 导入层

### P1-1　`Qty` 列从未被读，322 个 SKU 单位口径错位

`importers.py:45-46` 的 docstring 自己写着源表结构：

```
SS Code | Product Code | Description | Barcode | Qty | Current CNR | Current CNB | New CNR | New CNB
```

但 `_excel_layout` 只识别到价格列（`cur_cnr: 5, cur_cnb: 6, new_cnr: 7, new_cnb: 8`），
**`Qty`（第 4 列）从头到尾没人读**。

于是同一商品的两个渠道走了两套单位：

| 商品 | 名字 | cn_official | cn_trade | 比值 |
|---|---|---|---|---|
| 29-67 | CONTRAST: BAAL RED (18ML) (6 PACK) | ¥57 | ¥222.3 | **3.90** |
| 63-01 | WARHAMMER COLOUR: LAYER BRUSH SMALL (X6) | ¥52 | ¥203 | **3.90** |
| 66-37 | WARHAMMER PAINTING HANDLE (MK3) (6-PACK) | ¥52 | ¥203 | **3.90** |

全仓统计（`cn_trade / cn_official` 的分布）：

```
×0.65   1408 个   ← 正常的渠道折扣（65%）
×3.90    322 个   ← 6 × 0.65，多件装
×1.95     15 个   ← 3 × 0.65，三件装
```

**倍数精确到小数点后两位**，不可能是随机误差——这是"RRP 存单件、批发价存整包"。

**影响**：
- 这 322 个商品（315 涂料 + 22 模型）的「国内官店价」**低估 6 倍**；
- 如果它们被海外价匹配到，溢价率守卫（相对官店价）会算出 6 倍偏差，直接判 low 或误杀；
- 今天推送第 3 行正是这类：6 件装显示 `GBP 4.9 / ¥57`，实际整包应是 `£29.4 / ¥312`。

### P1-2　同一份 Excel 换一天再导会产生重复价格点

`observed_at` 默认取今天，所以"同一份调价表重复导入应覆盖"只在**同一天**成立；
换一天再导，同一价格会在 11-18、11-19 各留一条（实测 2 条 → 4 条）。

同时第二次导入的 stats 仍报 `price_points: 12`（统计的是"尝试写入"而不是"实际新增"），运维看不出没生效。

### P2-1　非法日期静默变成今天，未来日期照收

```
"2026-02-30" → 静默改成今天 2026-11-18，无警告
"2099-01-01" → 接受，latest_price_date 变 2099
```

### P2-2　表头识别退化会跳过第一行数据

表头认不出（无 CNR/CNB）时固定从第 3 行开始读，**第 2 行数据被跳过**（实测 98-01 丢失、98-02 入库）。

### P2-3　纯数字货号不归一，商品身份分裂

`9901` 与 `99-01` 会并存成两个商品；`"N/A"` 被当作"无新价"静默回退 Current，脏值伪装成正常价。

## 3. 匹配层

### P1-3　变体不进入匹配签名

`_tokens` 会**丢弃纯数字**，所以数字承载的变体信息全部丢失：

| 对比 | 相似度 | 结果 |
|---|---|---|
| `SEASON 2` ↔ `SEASON 3` | **1.000** | 完全无法区分 |
| `SPIKE! ISSUE 21` ↔ `ISSUE 22` | **1.000** | 完全无法区分 |
| 单瓶 `(24ML)` ↔ `(24ML) (6-PACK)` | 0.833 | **通过阈值 0.7** |
| `(24ML) (6-PACK)` ↔ `(24ML) (6PK)` | 0.667 | 反被误拒（真同规格） |

`edition_signature` 只认语言/限定词（`EDITION_TOKENS`），**不含 pack 数、容量、赛季、期号**。

### P1-4　生产库里 14 条海外价，1 条确定错配

逐条核对（`matched` 来自 note）：

| 商品 | 匹配到的 | £ | 判定 |
|---|---|---|---|
| **28-22** `AIR: EVIL SUNZ SCARLET (24ML) (6-PACK)` | `AIR: EVIL SUNZ SCARLET (24ML)`（**单瓶**） | 4.9 | **✗ 错配**，已入库为 high 并进入今天的推送 |
| 200-23 `BLOOD BOWL: OGRE` | `BLOOD BOWL: OGRE (SEASON 2)` | 22.5 | ✓（同 SKU，经外部核对编号 99120999011 一致） |
| 其余 12 条 | 同名/仅冒号差异 | — | ✓ |

**错配率 1/14 = 7.1%**（按 13 个唯一商品计 7.7%）。

### P1-5　`focus` 重抓段绕过品类过滤，错配永远清不掉

`cli.py` 的两段式抓取里，`focus` 段（重抓已有海外价的商品）**没有** paint/terrain/accessory 过滤，
而 `rest` 段有。结果 28-22（category=paint）每天都在重抓名单里，错配每天被重写一次。

### P1-6　英文版商品 100% 拒配

版本守卫要求"目标签名 == 匹配签名"。英文商品的名字带 `(ENGLISH)`/`(ENG)`，
而 Element Games 的商品标题**不带语言标记**：

```
target signature {english}  ≠  matched signature {}   → 拒绝
```

11 个名称含 `(ENG)`/`(ENGLISH)` 的 SKU 里 10 个在候选池，全部永远拿不到海外价，每次白跑浏览器。

### P1-7　分类准确率 63%

30 个真实商品名人工核对，**19/30 = 63.3%**。典型错例：

```
WARHAMMER 40K: CORE RULES (CHINESE)   → mini（应 book）
HORUS HERESY: LIBER ASTARTES (ENGLISH) → mini（应 book）
BLOOD BOWL: SPIKE! ISSUE 21            → mini（应 book）
WARHAMMER WATER POT (6-PACK)           → mini（应 accessory）
SPEARHEAD: CITY OF ASH                 → mini（应 boxed）
```

全表更客观的佐证：34 个含 `CORE RULES/LIBER/JOURNAL/SPIKE!` 的名称**全部**是 mini；
27/29 个 `SPEARHEAD:` 是 mini。分类错 → 品类族守卫失效 → 书可以被匹配到模型、涂料被当模型抓。

### P2-4　`save_overseas_points` 不校验 score

写入时不再复核相似度：实测传入 score=0.10 的同族错型号，仍 `saved=1, confidence=medium`。
阈值只在抓取层生效，绕过抓取直接调用 save 就没有防线。

### P2-5　`_similarity` 只处理 ASCII，中文名恒 0

`_similarity("战锤40K 禁军 寂静修女", 同一串) = 0.0`。人工 CSV 按 `sku_id` 挂已翻译商品时，
名称校验必然失败 → `unmatched`。

## 4. 展示层

### P1-8　"每日轮换"是假的：连续 16 天选同一批

`build_slot5_rows` 的排序键：

```python
abs(rowid * 2654435761 + seed) % 100003
```

种子只是**加在绝对值里**，属于保序变换的近似——实测：

```
seed 20261118 → 20270101（连续 16 个日期）：top5 完全相同
seed + 50000：才换 1 个
seed + 100003：又复原
```

而且排序第一层是 `(有海外价) DESC`，**13 个有 gw_uk 的商品永远排在最前**，
剩下 1732 个商品永远轮不到。所谓"轮换"在两层上都失效。

### P2-6　生产报告价格表 15 个格子是 `—`

今天报告的真实表格：

```
ARMAGEDDON BATTALION: DEATHWATCH   GBP 109   ¥1330   —   —   —   high
STORMCAST ETERNALS: VINDICTORS     GBP 39.5  ¥490    —   —   —   high
AIR: EVIL SUNZ SCARLET (24ML)(6-PACK) GBP 4.9 ¥57    —   —   —   high
ORKS: DEFFKOPTAS                   GBP 44    ¥545    —   —   —   high
DAUGHTERS OF KHAINE: WITCH AELVES  GBP 41.5  ¥499    —   —   —   high
```

「预期价 / 国内最低 / 涨跌」三列 **5 行全空**：
- 预期价只在"没有官店价"时出现，而 1745/1745 都有官店价 → **该列从未触发**（死列）
- 国内最低要求 ≥2 个"渠道+平台"组合，实际只有 3 个商品满足，且它们排不进前 5
- 涨跌要求同一渠道两天都有观测，实际只有闲鱼一条，且是不同卖家

### P2-7　涨跌把"换了一批卖家"当成"价格变了"

```
01-08 xianyu：11-17 ¥160（7 条样本）→ 11-18 ¥347.5（8 条样本）→ +117.2%
```

两个样本集合不同、最低价商品也不同（¥68 vs ¥98）。这是**卖家结构变化**，不是价格变化。
`price_movements` 只在 platform 不同时跳过，而实际写入端 platform 固定为"闲鱼"。

### P2-8　"多平台最低"按 (channel, platform) 计

两个闲鱼卖家 → 算"2 个平台" → 触发"国内最低"。而真实写入端平台名固定，同一渠道两个卖家反而只算 1 个。
口径随 platform 语义漂移。

### P2-9　人工 CSV 能覆盖系统平台价

人工 CSV 允许 `channel=xianyu` 且 `vendor=闲鱼`，`INSERT OR REPLACE` 会**直接覆盖**抓取到的真实价。
实测：01-08 的 ¥347.5 (high) 被替换成 ¥1.5 (medium)。`RESERVED_PLATFORMS` 里没有"闲鱼/淘宝"。

### P2-10　`LOW` 大小写可绕过置信度过滤

`best()` 用原始字符串 `!= "low"` 比较，`LOW` 会进最低价；写 `confidence='LOW'` 的 ¥10 被当国内街价展示。

### P2-11　坏配置会让整轮日报中断

`movement_days='abc'` → ValueError，而 `build_slot5_rows` 在 runner 的 try 之外 → 不渲染、不推送。

### P3

精度/标签不一致（`GBP 109.00 / ¥1,330` vs `GBP 109 / ¥1330`；"国内"vs"国内官店"vs"国内最低"）；
报告里置信度显示英文 `high`；`+0%` 仍标"有变动"；`data_date` 取全渠道而不是展示价日期；
`expected_note` 定义了但无人引用；`used_current` 死代码；`products.status` 死字段（全 active）；
`price_runs` 缺 id 3、4；`latest_points` N+1（`limit=-1` 时 1746 条 SQL）。

## 5. 架构评判

**做得对的**：

1. **写路径防线清楚**：负价/0 价/超大值/未知币种/缺汇率全部拒绝；唯一键 `(product_id, channel, platform, observed_at)` 生效，同键重复 0 行。
2. **品类族 + 版本签名**的思路是对的——问题只是**签名不完整**（缺 pack/season/容量），不是思路错。
3. **可解释的预期价模型**（汇率→运费→关税→加价→价差）公式自洽，输入校验有基本防线。
4. **展示层诚实**：没数据就是 `—`，不编造；`_safe_url` 挡住 `javascript:`。

**结构性问题**：

1. **单位（unit）不是一等公民**。整条链路里没有 `quantity`/`unit` 字段，导致"单件价"和"整包价"可以共存于同一个商品而不被发现。这是 322 个 SKU 出错的根因，也是溢价守卫失效的根因。
2. **匹配只做"名字像不像"，不做"规格一不一样"**。相似度天然分不清 `SEASON 2`/`SEASON 3`、`ISSUE 21`/`22`，因为数字被当噪声丢了。
3. **展示层与数据层脱节**：轮换逻辑写死在排序键里，没有可测的"这批商品为什么被选中"的解释；三列空数据的根因是选品条件与数据分布不匹配（1745 个都有官店价，却留了一列"没有官店价时才显示"）。

## 8. 已验证无问题

1. **负价 / 0 / 超大值**：Excel（`invalid=6`）、人工 CSV（`rejected=4`）、海外（负/0/超限全跳）都不写库。
2. **唯一键**：生产库同 `(product_id, channel, platform, observed_at)` 重复组 0 行。
3. **币种换算**：14 条 `gw_uk` 全部满足 `price_cny == round(price × 9.2, 2)`，0 偏差。
4. **CSV 编码**：GBK/GB18030/utf-8-sig 都能读，中文"闲鱼"行正常入库。
5. **人工渠道守卫**：`channel=cn_official`、`vendor=Element Games` 被拒。
6. **跨品类守卫**：paint vs mini 在 `save_overseas_points` 确实被跳过。
7. **空工作簿**：正确报错并返回非 0 退出码。
8. **`_safe_url`**：`javascript:`/`data:`/`ftp:`/空值全部返回空，不生成链接。
9. **同日幂等**：同一 DB 连续 3 次 `build_slot5_rows` 结果完全一致。
10. **空输入**：`price_movements` 返回 `{}`，`render_summary([])` 返回"没有匹配的商品。"。
