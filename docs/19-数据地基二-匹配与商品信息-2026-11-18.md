## 一、匹配层：670 / 1745 已对上

### 做法

`scripts/match_catalog.py`，两层：

1. **货号精确匹配**（第一层，最强证据）：零售站商品页标注的 `Product Code`（如 `99120108075`）
   与主表 `products.product_codes` 直接比对，命中即 1.00。
2. **名称 + 变体签名匹配**（第二层）：没有货号的走倒排索引 + Jaccard 相似度，
   阈值 0.75；命中前必须通过**变体签名**校验。

### 变体签名（这条直接修掉了审计里的 P1）

签名从**原始文本**抽（不能从 `_tokens` 抽，它会把数字丢掉）：

| 对比 | spec_ok | 结果 |
|---|---|---|
| `AIR…(24ML)(6-PACK)` vs `AIR…(24ML)` | **False** | 拒绝（原来会错配成单瓶价） |
| `…(24ML)(6-PACK)` vs `…(24ML)(6 PACK)` | True | 接受（同规格不同写法） |
| `BLOOD BOWL: OGRE` vs `…(SEASON 2)` | **False** | 拒绝 |
| `SPIKE! ISSUE 21` vs `ISSUE 22` | **False** | 拒绝 |
| `…(CHINESE)` vs 无语言标记 | lang_ok=True | 接受（英文市场默认无标记） |

实测：**28-22（6 件装）不再匹配单瓶**，审计里那条 6 倍错配从根上断掉了。

### 结果

```
商品 1745 个，目录 4797 条
匹配成功 671 个（0.75 阈值）
  得分 1.00：601 个
  得分 0.8–0.9：69 个
有候选但分不够：103（保守放弃）
无任何候选：6
```

抽样 12 条人眼核对，全部正确，包括：
- `BLACK TEMPLARS: GRIMALDUS & RETINUE` ↔ `BLACK TEMPLARS: CHAPLAIN GRIMALDUS & RETINUE`（0.80，同商品）
- `SHA'DAR HUNTERS & ARTHROMITE SPINEWYRMS` ↔ `NECROMUNDA: SHA'DAR HUNTERS…`（0.83，前缀差异）

## 三、结构升级：货号挂在目录上，而不是只挂在匹配结果上

原来的问题：`product_details` 以 `product_id` 为主键，只有"已匹配"的商品才有详情，
于是没法用货号去发现"名字匹配没找到、但货号其实对得上"的商品。

改法：给 `overseas_catalog` 加 `product_code` 列，新增
`scripts/fill_catalog_codes.py` **只取货号**（不抓描述，轻量），可分多次断点续跑：

```
已补 41 条（含 GW 数字码与第三方字母码 copinfbun 这类）
正在后台补全目录 4797 条
```

补完之后，匹配层第一层（按码）就能覆盖大部分商品——**不依赖名字，也不会受翻译/写法差异影响**。

## 五、货号验证：名称匹配准确率 96.4%，修正后 100%

详情页抓到的 GW 官方货号，和主表的 `product_codes` 是**两个独立来源**，可以直接拿来检验
名称匹配对不对：

```
可校验样本 669 条：645 一致 / 24 不一致 → 名称匹配准确率 96.4%
```

24 条错配分两类，都能定位：

| 类型 | 条数 | 例子 |
|---|---|---|
| 跨产品线同名 | 16 | `LEGIO CUSTODES: SHIELD CAPTAIN`（30k 树脂，码 …018）vs `CUSTODES: SHIELD CAPTAIN`（40k 塑料，码 …004） |
| 6PK 缩写没被签名识别 | 3 | `CONTRAST: X (18ML) (6PK)` 被当成单瓶 |

修法：

1. `_PACK` 正则补 `(\d+)\s*pk\b`（零售站常用缩写），`6PK` 现在能识别成 pack=6；
2. 新增 `prefix_conflict()`：两个名字的产品线前缀差在 `LEGIO/LEGION/HORUS/HERESY/HH` 上时判为不同商品；
3. 匹配时加**货号否决**：目录行的货号存在且与商品货号不一致 → 直接拒绝，名字再像也不认。

修完重跑：

```
按货号匹配 724 条 + 名称匹配 1 条 = 725 条
用货号复核：720 一致 / 0 不一致 / 8 无货号 → 可校验样本准确率 100%
```

顺带发现并挡掉：**目录里 380 条（7%）价格是 £0.00**（预售未定价），
这类不能当观测值，匹配时已按 `price > 0` 过滤。

### 涂料 15%：单位口径卡住 293 个 SKU

342 个涂料里 **293 个是 6 支装**（`B: X 12ML ROW X6`），Element Games 卖**单支**（£4.9/支）。
匹配器按变体签名正确拒绝——拿"6 支装价"比"单支价"就是错的。

要打通，必须先定一件事：**表里的 `¥57` 是单支价还是整包价？**
数据上 `cn_trade 222 ≈ 6×57×0.65`，说明 CNR 是**单支**、CNB 是**整包**——
这正是审计里「`Qty` 列没读」那条 P1。若确认单支，就能按单位价比：
¥57/支 vs £4.9≈¥45/支，中国贵 27%，这才是有意义的结论。

### 圣典 2%：版本不同

47 个圣典全是 `(CHN)/(CHINESE)`，Element 卖英文版。`lang_ok` 在双方都有语言标记且不相同时拒绝，
这是对的（不同版本定价与可得性不同）。

### 分类污染拖累覆盖

## 九、补课：小说（Black Library）

用户明确"不需要涂料价格，主要模型和小说"。查下来发现一个硬问题：

**主表里一本小说都没有。** 7 个 `book` 品类全是规则书（规则书/战典/将军手册），
因为主表来自 GW 中国调价表，那张表不带 Black Library 小说。

而 Element 有独立的 Black Library 区（`/games-workshop/BlackLibrary`），
落地页直接列小说，还有 4 个子分类（40k / AoS / 荷鲁斯之乱 / 涅克洛蒙达）。

### 做了三步

1. **抓取入口补上 BlackLibrary**，并让抓取器**也抽落地页自己的商品卡片**
   （原来只抽子分类页，会漏掉落地页直列的商品）。
   顺带发现 `/games-workshop/books` 是个空壳页，别被它骗了。
2. **补货号**：`fill_catalog_codes.py` 的分类过滤加上 `%blacklibrary%`，
   补了 153 条（47 条因超时失败，可再跑一次）。
3. **新脚本 `import_catalog_books.py`**：把「有官方码、主表没有、标题像书」的 SKU
   补进 `products`（`id` 用官方码，`category='book'`，`product_line` 按标题判断），
   再跑翻译。
