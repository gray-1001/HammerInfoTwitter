## 1. 改了什么

### D-02 · 渲染早于幂等判定

**问题**：已推送的日子再跑一次，`build_report()` 会先执行，把 `reports/{date}.html`
与 `latest.html` 覆盖成重算后的另一份——读者点开推送里的链接，看到的已经不是当时发的东西。

**改法**：把幂等判定整体前移到渲染之前。

```python
published_day = (not dry_run and not force
                 and (db.pushed_today(today) or db.pending_today(today)))
already = published_day and not skip_push
if already:
    log.warning("今日%s（%s），跳过排版与推送…")
    db.finish_run(run_id, "ok", stats)
    return stats          # ← 在 build_report 之前返回
```

同时补了一个漏洞：`--no-push` 预览时 `already` 为假，仍会渲染到站点根。
现在只要 `published_day` 为真，预览一律落到 `_dryrun/`，`write_latest=False`。

### D-03 · 发送与台账没有原子性、也没有跨进程互斥

**三处改动**：

1. **在途占位**：`delivery_ok` 变成三态 `0=失败 / 1=已送达 / 2=在途`。
   发送前先 `begin_push_batch()` 整批写 2，发送后 `finish_push_batch()` 改成 1 或 0。
2. **跨进程锁**：`RunLock` 用 `data/.run.lock`（pid + 时间戳）。
   计划任务的 `MultipleInstances=IgnoreNew` 只防同一任务重叠，防不住"手工重跑 + 计划任务同时跑"。
   遗留锁超过 2 小时自动接管。
3. **幂等口径**：`pushed_today or pending_today`——上次如果在"已发送、未确认"之间被杀，
   今天不再重发（宁可漏一次，不重复发）；`--force` 可强制重发。

**验证**：

```
begin_push_batch → delivery_ok=2，pushed_today=False，pending_today=True
finish(ok=True)  → delivery_ok=1，pending 消失
finish(ok=False) → delivery_ok=0，下次可以正常重试
锁：第二次 acquire 抛 RuntimeError；释放后可再拿；10000 秒前的遗留锁被接管
```

### D-08 / D-09 / D-10 · 失败可见性

| 编号 | 改法 |
|---|---|
| D-08 | `doctor --probe-push` 真发一条测试消息，成功 OK、失败 FAIL；`push.dry_run=true` 在正式配置下直接判 **FAIL**（以前只 WARN，等于每天"成功地"什么都不发） |
| D-09 | console 通道的 `stats["push"]` 从 `ok=True` 改成 `ok=False`，`cmd_run` 返回 **3**，任务面板不再显示成功 |
| D-10 | `except` 分支也写 `logs/alert.log`（以前只有推送失败才写，采集全挂/LLM 欠费/模板异常都不留痕） |

### D-11 · `--force` 失败覆盖已成功台账

`record_push` 的 upsert 改成：

```sql
delivery_ok = CASE WHEN pushes.delivery_ok = 1 THEN 1 ELSE excluded.delivery_ok END
```

已成功的行永远不会被后来的失败降级；`--force` 重推失败不会把当天改回"未送达"。

### D-12 · 已注册任务与安装脚本不一致

**重装前**（实机）：`python.exe` / `Interactive` / `RestartCount=0` / `Hidden=False`
**重装后**：`pythonw.exe` / `Interactive`（S4U 被系统拒绝，脚本自动回退）/ `RestartCount=3` / `Hidden=True` / `WakeToRun=True`

顺带修了脚本本身的两个坑：

- **重复执行会起第二个服务**：`Start-Process` 前先探端口（`Get-NetTCPConnection`），
  本次实跑输出"日报服务已在端口 8080 运行（PID …），跳过启动"；
- **端口硬编码 8080**：改成从 `config/config.yaml` 读 `report_port`；文件头注释也改成实际的"一个任务 + 一个启动项"。

## 3. 过程中自己引入、当场修掉的 2 个问题

这两个是这轮"边改边验"抓到的，如实记录：

### 3.1 重装任务后 doctor 立刻假红

重装任务会把 `LastTaskResult` 重置成 **0x41303（267011，任务尚未运行）**，
而 `_check_task` 把所有非 0 码都判 FAIL：

```
[FAIL] 定时任务  InfoTwitter-Daily 上次执行失败（LastTaskResult=0x41303）
1 项失败 / 1 项警告 —— 日报可能推送不出来
```

**修法**：识别任务计划程序自己的状态码——`267011` 尚未运行、`267009` 正在运行，
都改成 WARN；另外 `state == "running"` 也从 FAIL 改成 WARN（doctor 从任务里跑时会命中）。
修完输出：

```
[WARN] 定时任务  InfoTwitter-Daily 已注册但尚未运行过 · 下次 2026-11-18 12:00
2 项警告，功能可用但效果会打折
```

### 3.2 `--no-push` 预览会覆盖已发布日报

D-02 的第一版只挡了"要真正发送"的路径。但 `--no-push` 时 `already=False`，
渲染仍然写站点根——相当于预览把今天已发布的日报覆盖了。
补上 `published_day` 判断后，预览一律落 `_dryrun/`。

新增用例 `test_no_push_preview_writes_to_dryrun` 锁住这个行为。

### 3.3 附带发现：脚本 BOM 丢失

我改 `install_task.ps1` 时把 UTF-8 BOM 弄丢了，`powershell.exe` 5.1 按 ANSI 读中文，
直接报 `The Try statement is missing its Catch or Finally block`。已恢复 BOM 并加了语法校验。

## 4. 一个必须说清楚的限制

**D-02 的"已推送"判定依赖台账**。上一轮为了测试把 `pushes` 清空了，
所以现在系统认为"今天还没推过"——任何非 dry-run 的运行都会正常写站点根。
这不是 bug，是台账为空时的必然结果；明天 12:00 第一次正式运行之后，
这个保护才会真正起作用。
