## 二、规则 ①：约束替代特例 —— 聚类

### 改了什么

原来的合并规则是「两篇各含 2 个具体实体就 union」，靠往 `GENERIC_ENTITIES` 加词防误合并——补一个漏一个，所以同类事故发生了两次。

现在改成**三条必须同时满足的约束**（`pipeline.py:42-56`）：

| 约束 | 内容 | 防的是什么 |
|---|---|---|
| C1 | 共享实体 ≥2 **且** 标题 Jaccard ≥0.08 | 同一子版块的闲聊共享实体但标题无关 |
| C2 | 子集合并需 Jaccard ≥0.40 | 「XX 预告」被并进「XX 预告+全部报道」 |
| C3 | **簇级内聚度**：≥8 篇的簇，成员两两平均相似度 <0.20 就重切 | 并查集的传递闭包（A-B、B-C 连成 A/C） |
| C4 | 数据驱动泛化实体：出现在 >15% 文档里的实体不参与合并 | 新出现的泛词不用再手工加黑名单 |

同时修了中文分词（`pipeline.py:120-136`）：原来只有「词集为空」才退二元组，导致「战锤40K：暗潮…」这类标题切出整块 token、两篇同事件 Jaccard=0。现在只要有汉字就补字符二元组。

### 现场证据（生产库 969 篇重算）

```
改前：20 篇无关帖一个簇（均相似度 0.029，177/190 对 <0.1）
      17 篇把「战团包预售」与「Dawn of War IV 预告」并成一条
改后：
  Tilea 狮子、TTRPG 提问、Averlion 女兵、Osterwald 战役 → 各自独立（1/4/1/2 篇）
  战团包 → 7 篇（纯战团包内容）；Dawn of War IV 已单独成条
  最大簇 34 篇（Survivors 攻略，均相似度 0.308，属同一专题）
  中文最大簇 7 篇（B站系列视频），未出现过度合并
```

| `tests/golden_corpus.py` | 14 篇人工构造语料，分 6 组覆盖边界：同事件多措辞、同标题多源、只共享泛化实体、中文同事件、无日期、无关内容 |

五条断言分别对应五条教训：

1. **同输入跑两次结果一致**（确定性）
2. **打乱输入顺序结果一致**（可复现）——为此给 `_build_story` 的排序补了稳定键（`pipeline.py:344`），原来同一秒并列会退化成输入顺序
3. **与快照一致**（改规则必须显式刷新快照，而不是悄悄漂移）
4. **语义断言**：每组期望的 story 数（写死在 `EXPECTED_STORIES`）
5. **泛化实体绝不合并**（上一轮事故的回归点）

为了让分数也进快照，给 `score_story` / `score_cn_story` 加了可注入的 `now`（时效分依赖当前时间，不固定的话快照过一天就漂）。

## 四、规则 ④：状态机终态与恢复

### 现状问题

推送台账有三个状态：`1=已送达 / 0=失败 / 2=在途`，但**没有从 2 出来的恢复路径**。进程在 `begin_push_batch` 之后被杀（任务超时/断电），这一行永远是 2；下次运行 `pending_today` 命中直接返回 `already_pushed`，`runs.status=ok`、退出码 0、无告警——当天静默不推。

### 改了什么

`db.py` 新增 `reconcile_inflight()`：启动时把超过 15 分钟仍停在 2 的行收敛成 0（失败），返回被收敛的行。

`runner.py` 在幂等判定之前调用，并写 alert：

```python
if not dry_run:
    stale = db.reconcile_inflight()
    if stale:
        log.warning(...)
        _write_alert(cfg, today, msg)
```

语义边界写进了测试：**已送达（1）永不降级**、**刚发出的在途（2）不被误判**、**收敛幂等**。

## 五、规则 ③：失败分类计数与告警

正文抓取是最大的静默失败源（核查发现 904 篇里 708 篇正文不足 200 字，日志却打「完成」）。

`content.enrich_docs()` 现在接受一个 `stats` 字典，填充分类计数：

```
targets / cached / requested / ok / failed / updated / date_fixed / url_fixed
```

`runner.py` 把它写进 `runs.stats["content_fetch"]`，并在**请求数 ≥10 且失败率 ≥50%** 时写 alert。

> 注意：这条只解决「看不见」，不解决「抓不到」。正文成功率本身要等第 2 批（C-01~C-07）。

## 六、顺手修掉的：槽 5 轮换

`pricing/summary.py:65` 原来是 `ABS(rowid * C + seed) % 100003`——种子每天 +1 等于给所有键同时 +1，取模后只是循环移位，实测连续 7 天 top5 完全一样。

改为 `ABS(rowid * (C + seed * 7919)) % 100003`：让种子改变**步长**而不是加常数。

```
改后 seed=20261113…20261119：
['01-11','01-08','99120209054','99120106056','69-20']
['01-08','01-11','99120201021','99120210035','301-43']
...
7 天共 7 种不同组合
```

## 八、一个需要留意的副作用

聚类规则变了，**故事的身份会变**：昨天被错误合并的大簇会被拆开，拆出来的部分拿到新的 `story_id`。而跨日去重是按 `story_id + status` 做的，所以拆分出来的内容**可能被当成新事件再推一次**。

时间窗口（48h）+ 文章龄（一周）会把影响压到很小，但明天 12:00 那次值得盯一眼：如果出现「内容眼熟但标题是新的」，就是这次拆分造成的，属一次性影响。

彻底解决要等 P-17（台账改逻辑删除，保留「曾推送过」的内容指纹）。
