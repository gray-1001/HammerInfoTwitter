## 1. 逐项改动

### P0-1 浏览器源日期错配（根因）

**问题**：取日期时对每一级祖先整棵子树 `querySelector('time')`，会抓到侧栏「最多阅读」里别的卡片。

**两层修复**：

1. **列表页**：只接受"属于本卡片"的 `<time>`——要么它最近的 `<a>` 就是当前锚点，要么这一层只有当前这一个文章链接；容器里出现多个文章链接就不再往上爬。

```js
const owner = t.closest(ARTICLE);
const links = node.querySelectorAll(ARTICLE).length;
if (owner === e || links === 1) { dt = ...; }
```

2. **文章页兜底**（新增）：`content.enrich_docs` 本来就逐篇打开文章页，顺手解析 JSON-LD `datePublished` 回写 `raw_docs.published_at`；对已缓存、不再抓正文的文档，新增 `backfill_dates()` 做限额补扫（每轮 20 篇）。

**实测**：列表页修复后 6 条正确 / 4 条取不到（不再是"取错"）；接上文章页兜底后 **10/10 全部正确**，无日期清零。

**生产库修复**：`scripts/repair_published_dates.py --all` 重算 WHC 全部 21 行，修正 **15 条**（11 条空 + 4 条错日期）。

### P1-1 收回 L0 兜底

无发布时间的 story 一律不进一级（不再区分 L0）。既然日期能回填，就没有"必须放行"的理由。

### P1-2 分层改用「首次出现」

`ref = dt`（first_seen）而不是 `pub or dt`。文章日期只用于时效计分和「超过一周」的排除；二级衰减也按首次发现天数算。

**实测**：

```
文章 72h 前发布、1h 前才发现  → qualified（一级），修复前是 aged
文章 10 天前发布               → 排除
```

### P1-3 窗口与保留期改用入库时间

- `recent_raw_docs`：`COALESCE(discovered_at, published_at, fetched_at)`
- `prune_raw_docs`：`COALESCE(discovered_at, fetched_at)`

迟到的新闻（文章旧、今天才抓到）现在能进分析窗口，也不会被立刻删掉。

### P1-4 事件身份三处加固

1. **CJK 短标题**：`token_set` 原来要求 `len > 2`，把「分家」这类两字标题的词集清空 → 永远不聚类。现在两字 CJK 词保留，实在为空时退回字符二元组。
2. **候选 id 排序**：`(first_seen, id)` 双键，同秒候选不再受 set 迭代顺序影响。
3. **合并优先已推送 id**：`merge_same_title(stories, pushed_ids=...)` 的排序键改成「已推送 → 最早出现 → 高分 → id」，避免合并把去重键换掉导致次日重推。

### P3-2 时间来源落库

`stories` 新增 `time_source` 列（迁移自动补），`insert_story` 写入，`backlog_candidates` 排除「fetch 且无 published_at」的行——堵住从历史补位绕回推送的后门。

## 3. 修复过程中发现/引入的问题（如实记录）

### 3.1 修复中发现的：列表页只剩 6/10

改完选择器后，4 条从"错日期"变成"没日期"。这不是新 bug，而是把**污染**变回了**缺失**——
原来的错日期掩盖了"这些卡片本来就取不到日期"的事实。靠文章页 JSON-LD 兜底补齐。

### 3.2 缓存文档不走正文抓取 → 补扫

`enrich_docs` 对缓存命中的 URL 直接跳过，所以已入库的老文档永远拿不到日期。
新增 `backfill_dates()`：只补日期、不抓正文，每轮限额 20 篇。

### 3.3 自己写的一个测试失败了

上一轮为「L0 兜底」加的测试 `test_undated_official_story_uses_first_seen` 现在必然失败——
因为行为被有意收回了。已改写成 `test_undated_official_story_also_excluded`，
断言"官方源无日期也不能当今日新闻"。这是**预期内的失败**，不是回归。

### 3.4 首次运行时被自己的锁挡住

12:00 任务启动后，我的 dry-run 被 `RunLock` 拒绝（`锁被占用（15 秒）`）。
说明锁生效；但也暴露 P1-6 还没修：锁冲突时 CLI 返回 0。这条留在第 2 批。

### 3.5 一个观察（未处置）

今天推的 4 条里，最早发布日期是 11-11（7 天前），但它们都是**今天才第一次被发现**。
按设计 §20「一级 = 首次出现 ≤48h」，这是正确行为；但读者可能觉得"这不像今天的新闻"。
如果要更严格，可以把一级再叠加一条"文章日期不超过 N 天"，这是产品口径决策，留待确认。
