### 2.2 D-01 · 纯价格日"发了不记账"

**改法**：`_record_pushes` 的槽 5 判定从 `slots["product"]` 放宽到 `slots["product"] or slots["product_rows"]`；再加一条兜底——真的什么都没记时写一行 `slot=0`，保证"已投递"这件事对系统可见。

**验证**：

### 2.3 S-02 · 来源定级失真

原来是三层错误叠在一起：

1. **拿不到发布域名时继承查询源的层级**：`gnews_gw_results`(L1) 会把 `uk.investing.com` 一律按 L1 计权威；
2. **聚合器域名被当成独立信源**：`independent_sources` 回退到 URL 域，`news.google.com` 要么把两条不同媒体压成一个，要么和一条真实 RSS 凑成"两个独立来源"虚假升级；
3. **存量数据没有回填**。

**改法**：

```python
# adapters：只有 site: 限定的查询才天然知道发布方是谁
site_restricted = "site:" in str(source.get("query") or "").lower()
tier = DOMAIN_TIER.get(src_domain) or (source.get("tier", "L2") if site_restricted else "L2")

# pipeline：聚合器只证明"被收录"，不参与独立来源计数
AGGREGATOR_DOMAINS = {"news.google.com", "feedproxy.google.com", "flipboard.com", ...}
```

**回填**：新增 `scripts/backfill_source_tier.py`（支持 `--dry-run`），按同样规则重算存量行的 `derived_tier`。

```
源                    待修正    默认层级
gnews_aos                2        L2
合计修正 2 行
```

回填后的层级分布变得合理了（`gnews_40k`：L0 5 / L1 13 / L2 31，来自真实发布域名），而不是所有行都等于查询源配置的层级。


## 四、期间发现并顺手修掉的一个真问题

做 S-02 时发现 `derived_tier` 在 `pipeline.py` 里**根本没有被读取**——它只出现在 `db.recent_raw_docs` 的 SQL 里（`COALESCE(r.derived_tier, s.tier)`）。也就是说这条链路是通的，但只对**新写入**的行生效；存量行 `derived_tier` 为 NULL 时会回退到源配置层级，正是第 1 条问题的成因。回填脚本补上了这一环。
