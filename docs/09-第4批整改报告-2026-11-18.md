## 1. 第 4 批：采集层

### C-04 · Cloudflare 挑战不重试

浏览器适配器遇到 `just a moment` 直接 `break`，等于对这类站点零重试。

**改法**：挑战也走重试——第一次等 3 秒再看，第二次才放弃；整个源失败时只计一次熔断。

### C-06 · B 站把网络异常当 cookie 失效

`-500`、网络超时都会删 `cookies_bili.json` 并重新开浏览器取 cookie。4 个 B 站源各失败两次 = 最多 8 次 Chromium 启动。

**改法**：只有 `-412 / -401 / 412`（鉴权）才清 cookie；网络异常和服务端错误保留。

### C-07 · 正文缓存 TTL 读取时不生效

`cache_get` 只看 `url_hash`，而 `prune_content_cache` 排在 `enrich_docs` **之后**——过期后的第一次运行仍然复用旧抽取结果。

**改法**：`cache_get(..., max_age_days=...)` 读取时就判过期，`enrich_docs` 传 `retention.content_cache_days`。

### C-08 · `max_items` 是空转

`max_items=len(to_fetch) or 1` 恒等于全量，唯一的边界是 30 分钟 deadline，而 deadline 只在每篇**开始前**检查，单篇最坏 90 秒。

**改法**：新增 `content.max_items`（默认 60）作为真正上限；`_fetch_one` 内部也检查 deadline。

### C-09 · 付费墙检测只看前 600 字

**改法**：扫前 2000 字。实测标记落在第 1120 字时能识别（用例 `test_marker_deep_in_text`）。

### C-10 · 超时与重试头

- RSS/GoogleNews 这类小响应单独 15s 读超时（原来是 30s × 4 次 ≈ 128s/URL）；
- `Retry-After` 支持 HTTP-date（原来 `float()` 解析失败就整条忽略）；
- 500 加入可重试状态码。

### C-11 · `sources.weight` 是死配置

没有任何代码读取它。不删字段（将来接源权重不用改配置），但在 `sources.yaml` 头部写清楚"当前未被使用"，免得调参时误以为有效。

### C-12 · SOCKS 代理让整轮采集崩掉

`ALL_PROXY=socks5://…` 时 `httpx.Client(proxy=...)` 在构造阶段抛 `ImportError`，而构造发生在 `collect()` 的 per-source try **之外**。

**改法**：`Fetcher._build_client` 捕获 `ImportError`/`ValueError`，记 error 日志并降级直连。

```
实测：Fetcher(proxy='socks5://127.0.0.1:1080') → proxy 置 None，client 正常创建，不再抛异常
```

## 2. 价格模块有效性补课

### 2.1 每日轮换

`build_summary` 的排序原来是 `(有海外价, 有街价, updated_at, id)`。1745 个商品的 `updated_at` 全是同一天，所以实际退化成 id 顺序——**槽 5 每天一模一样**。

**改法**：加入每日种子项 `ABS(rowid * 2654435761 + seed) % 100003`。有信号的商品（海外价/街价）仍然排最前，其余"只有官店价"的商品按天轮换。

```
11-18: 39-13, 01-10, 01-08, 01-11, 30-88 MIDDLE-EARTH SBG…
（第 5 位从前几天的 01-07 换成了 30-88）
```

### 2.2 把"数据缺口"写在报告页上

新增 `price_coverage()`，报告页槽 5 下面直接写明：

```
价格覆盖：1745 个商品中，2 个有国内渠道价、1 个有海外价；
历史观测 1 天（2026-11-17 ~ 2026-11-17）
⚠ 只有一天的观测，所以「涨跌」暂时无法计算
⚠ 渠道价样本很少，下表多数商品只能给出官方价
```

这不是装饰——它让"价格模块看起来很空"这件事变成可验证的事实，而不是让读者以为这就是全部市场信息。

## 6. 追加诊断：价格模块为什么是空的（2026-11-18）

**结论：不是爬取阶段的问题。抓取成功了，数据也在，是被正确清理掉了。**

### 6.1 完整时间线（有日志可查）

| 时间 | 事件 | 价格点总数 |
|---|---|---|
| 16:42–16:44 | 导入 GW 调价表（1765 行 → 1745 个商品，3490 个价格点） | 3490 |
| 16:48–16:50 | Element Games 海外价，连跑 4 次，5/6 命中（匹配度 0.75–1.00） | **3495** |

### 6.2 那 4 条为什么被删——删得对

| 商品 | 名字 | 抓回来的匹配 |
|---|---|---|
| 40-02 | WARHAMMER 40K: CORE RULES **(CHINESE)** | `CORE RULES`（英文版） |
| 40-04 | WARHAMMER 40000: INTRODUCTORY SET **(CHN)** | `INTRODUCTORY SET` |

只有 `39-13 ARMAGEDDON BATTALION: DEATHWATCH`（没有中文版标记）是真匹配，留下来了。

**所以现在的"1 条海外价"是正确状态，不是抓不到。**

### 6.3 真正让模块空着的三个原因

1. **结构性错配**：商品主表来自 GW **中国区**调价表（118 个商品明确是国内版），
   而 Element Games 是英国零售商、卖英文版。抓了也会被版本守卫拒。
   这次只抓了 6 个，恰好 4 个撞上。
2. **国内价链路几乎没有输入**：`--fetch-cn` 的 SQL 只选 `name_zh` 非空的商品，
   而中文名只有 **5 / 1745**。所以"全国内价抓取"的队列其实只有 5 个商品。
3. **没有任何一环是自动的**：日更链路里只有 `auto_refresh`（导 CSV）。
   调价表只导过一次 → 只有一天观测 → 涨跌永远算不出来。

### 6.4 本轮顺手修的两点

- **`purge` 现在写 `price_runs`**：删除操作第一次有审计痕迹（这也是之前误判成"只有 1 个商品有海外价"的原因——删了没人知道）。
- **`--fetch-overseas` 排除中文版商品**：候选池从"全部非涂料商品"收敛到 **1471 个**，
  不再白跑那 118 个必被拒的。

## 7. 抓取策略调整与实跑结果（2026-11-18 10:50–11:08）

### 7.1 原来的策略错在哪

1. **永远取同一批**：`ORDER BY updated_at DESC LIMIT N`，而 1745 个商品的 `updated_at` 完全相同 → 每天只试前 N 个。1745 个里实际只试过 6 个。
2. **中文版商品白跑**：候选里混着 118 个 `(CHINESE)/(CHN)` 商品，抓回来必被版本守卫拒。
3. **匹配算法把对的判成错的**：`COMBAT PATROL: BATTLEZONE` vs `WARHAMMER 40.000: COMBAT PATROL: BATTLEZONE` 是同一个商品，Jaccard 只有 0.50，被 0.7 阈值拒掉。
4. **只抓不重抓**：纯轮换会让每个商品永远只有一天观测，涨跌永远算不出来。

### 7.2 改了四处

| 改动 | 内容 |
|---|---|
| 候选过滤 | 排除中文版 / 涂料 / 地形 / 配件；涂料识别补上 `\d+ml`（存量 192 个商品重新归类） |
| 两段式取样 | 一半重抓"已有海外价但观测最旧"的（攒历史），一半扩展"从没抓过"的（扩覆盖） |
| 轮换 | 扩展段按周种子打散，不再固定前 N 个 |
| 打分 | 去掉品牌噪声词（warhammer/40k/40.000/games workshop…）后再算 Jaccard |

打分验证（8 个用例全过）：

```
COMBAT PATROL: BATTLEZONE  vs  WARHAMMER 40.000: COMBAT PATROL: BATTLEZONE  0.50 → 1.00 ✅
VOID WAR BASES            vs  BOARDING ACTIONS: VOID WAR BASES              0.60 → 0.60 ✅ 仍拒
CUSTODIAN GUARD           vs  CUSTODIAN WARDENS                             0.60 → 0.60 ✅ 仍拒
```

### 7.4 涨跌为什么还是 0 组

13 个商品里有 12 个只有一天观测；唯一有两天的 `39-13` 两天同价（¥1003 → ¥1003），
按规则 `abs(差) < 0.01` 不算变动。

**明天再跑一轮重抓**，就会出现第一组真实涨跌（前提是价格真的变了）。

### 7.5 单次成本

20 个商品约 4 分钟（含浏览器启动与 2s 间隔）。1471 个候选全量约 5 小时，
建议每天 30–50 个滚动覆盖，一周能到 200–350 个。
